# doc-kit

doc-kit: a documentation kit for writing slides and papers from shared math, graphics and plotting assets.

- **Slides:** one Markdown file per talk, rendered in the browser with no build step. KaTeX math,
  Mermaid diagrams, D3 plots, per-click reveals, speaker view, PDF export. Everything is vendored,
  so talks work offline.
- **Papers:** the same equations through a generated LaTeX package (`\usepackage{ex}` +
  `\exasset{...}` for the example pack), the same diagrams as PDF, and the same plots as PDF.
- **Plots:** `doc_kit.plots` reads W&B CSV exports and writes each figure as SVG (slides) and PDF
  (papers) in one call, styled to match the slides.

**The tool is separate from the content.** This repo holds the engine, the CLI, and one generic
example pack and talk. Your talks and your asset packs (theme, notation, equations, diagrams) live
wherever you like: a private repo, a project's `docs/` folder, or a local directory.

## Install

```sh
pip install "doc-kit[tools] @ git+https://github.com/madyarc/doc-kit"
# or, from a clone:  pip install -e ".[tools]"
```

`[tools]` adds Selenium for `check`, `pdf`, `math-check` and `graphics`, which also need
**Firefox**. `math-check` uses **pdflatex** for its LaTeX half.

## Quick start

```sh
doc-kit serve path/to/talk.md          # then open the printed URL; the page reloads when you save
doc-kit check path/to/talk.md          # every slide and step, light + dark: errors, overflow, pending data
doc-kit build path/to/talk.md --pdf    # standalone folder (host anywhere) + PDF, in <talk dir>/build/
```

Try it on the example: `doc-kit serve talks/example/talk.md`.

| Key | Action |
|---|---|
| → / space / click | next step (a click on the left quarter goes back) |
| ← | previous step |
| Home / End | first / last slide |
| number, then Enter | go to that slide |
| `t` | light / dark |
| `s` | speaker view in a new window (notes, next step, timer), kept in sync |
| `f` | fullscreen |
| `?` | key help |

URLs: `#/5` is slide 5, and `#/5.2` is slide 5 at step 2. `?theme=dark` forces a theme.

## Commands

| Command | What it does |
|---|---|
| `doc-kit serve TALK.md [--port 8000]` | serve a talk from any folder, with live reload |
| `doc-kit check TALK.md [--shots DIR] [--all-steps]` | headless check in both themes; exits 1 on errors or overflow |
| `doc-kit build TALK.md [-o DIR] [--pdf] [--no-html]` | standalone folder (talk + engine + packs) for any static host, and/or a PDF |
| `doc-kit pdf TALK.md [--steps] [--theme dark]` | PDF, one page per slide or per click |
| `doc-kit packs` | list the packs doc-kit can find |
| `doc-kit math-check [PACK ...]` | every math asset in KaTeX (strict) and pdflatex |
| `doc-kit sty PACK [--bundle DIR]` | the pack's LaTeX package (`<prefix>.sty`) |
| `doc-kit graphics PATH ...` | `.mmd` → `.svg` → `.pdf` for papers, in the pack's theme |

A built folder must be served over HTTP (e.g. `python3 -m http.server -d build/talk`), because
browsers block decks opened as `file://`. For email, send the PDF.

## Talks and packs

A talk is a folder with a `.md` file, plus its `data/` and `figures/`. It selects an asset pack in
its front matter:

```yaml
---
title: My talk
pack: ../../packs/mylab     # a path, relative to the talk file
# pack: mylab               # or a name, found on DOCKIT_PACKS or among the packs shipped with doc-kit
---
```

`DOCKIT_PACKS` lists folders separated by `:`. Each entry is either a pack itself (it has
`pack.yaml`) or a folder of packs. Earlier entries win. doc-kit ships one pack, `example`.

A typical project layout, outside this repo:

```
myproject/docs/
  packs/mylab/                 pack.yaml, math/, graphics/
  talks/mytalk/talk.md         pack: ../../packs/mylab
  talks/mytalk/data/  figures/
```

This repo's `.gitignore` ignores everything in `talks/` except `talks/example/`, so a talk
dropped here by mistake isn't committed.

### Pack layout

```
<pack>/
  pack.yaml
  math/        equation assets (.tex) + macros.tex (shared notation)
  graphics/    theme.css, fonts/, logo.svg, slide assets (.md), diagrams (.mmd/.svg/.pdf), matplotlib.mplstyle
  latex/       generated by `doc-kit sty` (don't commit; it holds absolute paths)
```

```yaml
# pack.yaml
name: My Lab
math: math
macros: math/macros.tex         # shared notation, read by KaTeX and by the LaTeX package
latex:
  prefix: mylab                 # \mylabasset, \mylabparam, \mylabdefaults; package mylab.sty
graphics: graphics
styles: [graphics/fonts/fonts.css, graphics/theme.css]
logo: graphics/logo.svg         # optional
footer: My Lab · My University
matplotlib: graphics/matplotlib.mplstyle
```

To start a pack: copy `src/doc_kit/packs/example/` somewhere, rename it, and edit `pack.yaml`,
the theme and the assets.

### Resolving `::: use` names

- `::: use demo/heat` looks for `math/demo/heat.tex`, then `graphics/demo/heat.md`.
- `::: use math/...` or `::: use graphics/...` picks one explicitly.
- `::: use otherpack:name` reaches into another pack, found by name.
- A math asset becomes display math. Add `inline` for inline math.
- An indented `::: use` (e.g. in a list item) indents what it inserts.

### Math assets (`math/**/*.tex`)

- One LaTeX math body per file, with no blank lines (a blank line is `\par`, illegal in math).
- `%` comments are fine.
- With the pack prefix (here `ex`), an asset can use:

| In the asset | Meaning |
|---|---|
| `\exdefaults{k=v, ...}` | defaults for parameters the caller did not set |
| `\exparam{k}` | the value of parameter `k` |
| `\exasset[k=v]{name}` | another math asset. The caller's parameters are inherited |
| `% check: k=v; k=w` | extra parameter sets for `doc-kit math-check` |

Slides and papers apply the same rules: the engine's `math.js` on one side, the generated `.sty`
on the other. `macros.tex` uses `\providecommand` only, so it never overrides a journal class.

**In a slide:** `::: use demo/heat kappa=0.1`.

**In a paper:** `\usepackage{ex}`, then
`\begin{equation}\exasset[kappa=0.1]{demo/heat}\label{eq:heat}\end{equation}`.
See `papers/example/`.

### Slide assets (`graphics/**/*.md`)

- A slide asset is a Markdown fragment, which may contain `---` and so be several slides.
- Its front matter declares parameters, and `{{name}}` (or `{{name|fallback}}`) substitutes them.
- `::: part name` … `:::` marks a piece that `::: use asset part=name` pulls in on its own.
- Relative paths resolve against the asset file.

## Writing a talk

- `---` on its own line separates slides.
- The first `#`/`##` heading is the slide title.
- `<!-- slide key=value ... -->` sets options:
  - `layout`: `default`, `title`, `two-col`, `figure`, `equation`, `section` or `blank`;
  - `section`: the footer label, which carries over to the following slides;
  - `class`: e.g. `class=dense` or `dense2`;
  - `footer=false`.
- `macros:` in the front matter adds KaTeX macros for one talk.

| Block | What it does |
|---|---|
| `::: col 3` | a column. Consecutive columns form a row; the number is the relative width |
| `::: spacer` | ends a row of columns, so the next columns start a new row |
| `::: steps` / `::: steps rows` / `::: steps start=2` | list items, or table rows, appear one click each |
| `::: step 3` | this block appears at click 3 |
| `::: notes` | speaker notes |
| `::: figure src=fig.svg caption="..."` | figure. SVGs are inlined so `currentColor` follows the theme; a missing file shows a placeholder |
| `::: placeholder Title` | a dashed "pending" box |
| `::: frame src=app/index.html` | an embedded page |
| `::: anything extra` | `<div class="sk-c-anything sk-c-extra">`, styled by the pack |

Any block accepts `step=N`. Inside math:
- `\step{n}{…}` reveals a term at click n;
- `\hl{n}{…}` and `\hlb{n}{…}` highlight it, with `n-` meaning from n on and `n-m` a range.

These are slide-only, so keep them out of math assets. `[[tbd]]` marks pending values.

Components (fenced code blocks):
- **`mermaid`:** inline, or `src=diagram.mmd` with per-click `%% step N: nodes` and `%% hl N: nodes`.
- **`plot`:** W&B CSV line or bar plots, with `reveal: series`, log axes, `__MIN`/`__MAX` bands, and a placeholder when the CSV is missing.
- **`fnplot`:** analytic curves, bands and reference lines.

See `talks/example/talk.md`.

## Plots (`doc_kit.plots`)

```python
from doc_kit import plots

plots.use_style("example")          # pack name or path: fonts, palette, line widths
fig, ax = plots.plot_runs(["data/l2.csv"], key="l2_error", log=True)
plots.save(fig, "figures/l2")       # figures/l2.svg (slides, follows the theme) + figures/l2.pdf (papers)
```

## Offline

Everything the slides need is in the package (engine, vendored libraries) and in your pack and
talk folders. `doc-kit serve` runs on 127.0.0.1 and needs no internet.
